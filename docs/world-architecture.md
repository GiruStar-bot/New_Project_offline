# v0.2 実装メモ

## 責務と流れ

`scenes/world.tscn` → `world_controller.gd` が1つの `world_state.gd` を所有する。毎フレームの実時間はこの所有者から一度だけ状態へ渡す。UIの描画頻度やカメラの位置はシミュレーションを変えない。

- `geography.gd`：陸地・島・河川・崖・橋・標石。政治的所有権に依存しない不可視の可視性グラフとAStar2Dで経路を返す。
- `border_treaty.gd`：確定国境、編集中の提案、領土ポリゴン、交換面積、仮のNPC判定、合意時の更新。
- `world_state.gd`：人物の所属・所在・命令、移動と巡回、時計、公開命令の検証、記録。画像や画面サイズに依存しない。
- `map_view.gd`：カメラと入力座標変換。クリック・ドラッグをシグナルで通知。世界を直接更新しない。
- `world_map.gd`：仮アートの地形・領域・拠点・人物・選択経路の描画。
- `world_controller.gd`：意図を状態APIへ渡し、結果と理由をUIへ反映する。

人物のID・所属と現在の所在領土は別に保持・計算する。拠点の所属も国境編集で自動変更しない。国家滅亡・軍事占領・人材の心理・経済は後続段階の責務として設計資料に記録している。

## 最小API

| API | 結果 |
| --- | --- |
| `issue_move(id, destination)` / `issue_patrol(id, destination)` / `halt(id)` | `ok` と理由を返す。無効な命令は既存の行動を変更しない |
| `set_paused(value)` / `set_speed(1/2/4)` / `advance(real_seconds)` | 共通の固定刻み時計を制御 |
| `begin_proposal()` / 点の移動・挿入・削除 | 確定国境を保持したまま提案を編集 |
| `submit_proposal()` | 形状と面積の検証、NPCの判定。合意時のみ両国を同時更新 |
| `cancel_proposal()` | 提案だけを破棄 |

`changed` はUIの再評価に使い、移動は共通時計の中で進める。メッセージや表示から行動を再実行しない。初期化ではカメラ以外の状態を新しくし、信号接続も新しい所有者へ付け替える。

## 国境の幾何

固定の両端を持つ北から南への折れ線を、両国が共通の境界として使う。各国の海岸輪郭と境界を合わせたポリゴンで領土を表す。点と線が本土内にあること、北南順、非自己交差、非分断、拠点の維持、ポリゴンの重複・面積保存を確認する。

提案後の自国領から現在の自国領を引いた領域が自国の取得面積。相手国も同様に計算する。Geometry2Dの差集合の符号付き輪郭を使い、穴の向きを面積に反映する。仮の面積単位は地図座標の二乗。

対象は両国の本土境界のみで、無所属の北部と島は交渉に参加しない。軍の占領や海上利権をこの領域へ混同して実装しない。

## 仮数値と技術設定

| 設定 | 値 | 理由 / 扱い |
| --- | --- | --- |
| 人数 | 24 | `[PLACEHOLDER]` 個人操作を小規模で検証 |
| 移動速度 | 50/30座標単位/ゲーム秒 | `[PLACEHOLDER]` 1倍速で従来の50座標単位/実秒を維持。地図縮尺と実際の歩行速度は未確定 |
| NPCの取得/譲渡比 | 0.95以上 | `[PLACEHOLDER]` 面積だけの取引。ほぼ同面積を許容 |
| 拠点と境界の距離 | 40座標単位以上 | `[PLACEHOLDER]` 村・城塞の仮敷地を保護 |
| 標石への吸着 | 18座標単位未満 | `[PLACEHOLDER]` 境界の点を置きやすくする |
| 国境の編集点 | 最大32 | 試作の計算負荷を抑える技術制限 |
| 境界の北南間隔・海岸間隔 | 4座標単位以上 | 接触と縮退で国の領域が分断されるのを防ぐ技術許容幅 |
| シミュレーション刻み | 3ゲーム秒 | 通常速度で0.1実秒ごと。速度変更時も同じ移動更新を適用する技術設定 |
| 時計の速度 | 30ゲーム秒/実秒 | ユーザー確定値。2倍速60、4倍速120 |

無効入力、95%条件の両側、島の非到達、海岸を横切る線などを自動テストする。v0.3の資源・仕事・税の仮設定と検証結果は [経済設計](economy-design.md) に記録する。給与と高度な委任は後続の更新。

## 検証用スクリプト

`world_save.gd` はデータだけのJSON形式（version 3 / fixed-world-v1）。固定の地理・拠点・既知の作業場は同じ地図から再構成し、時計、手動停止と政治調整の停止、人物、命令、国境、履歴に加え経済を保存する。カメラ・選択・GUIノードは保存しない。24人の現在の試作専用で、人口拡大時には形式を更新する。

version 1は人物・命令・tick回数を維持し、時間端数を30倍してversion 2へ移行する。表示上の経過時間も以前の30倍になる。旧データの未確定提案は政治調整の停止として復元する。それ以外の未対応形式は拒否する。

version 1/2で経済状態がない場合は、現在の経過日数から初期経済を開始する。過去の収穫・税・消費を実行しない。version 3の経済が欠落・不正なら拒否する。既存の人物命令を保ち、新しい仕事は未割当とする。

## 生活と生産の更新

`economy.gd` は個人24口座、国庫3口座、作業場9か所、日内労働、農作業の蓄積、当月の生産と徴収、12件までの月次決算を保持する。位置と人物の命令はWorldが所有し、経済の参照IDと担当枠を保存する。

`World.assign_job(id, site_id)` は自国住民、作業場所有、定員、枯渇、経路を確認してから仕事を変更する。担当枠ごとに異なる作業位置を予約し、同じ場所へ全員が重ならない。到着までの時間は生産に使わない。移動完了時の余った刻みだけを労働へ計上し、それまでの労働は日内集計として維持する。移動・巡回・解除は仕事の予約を解除する。

3ゲーム秒の共通更新で労働秒を記録し、86400秒境界で1回だけ日末処理をする。日末には採取・農作業の蓄積、必要時の収穫、月末の税と維持費、生活消費、月末報告を順に処理する。将来の輸送まで国庫と個人間の徴収・配給は即時の帳簿移転として抽象化する。

税率と自動配給は政治調整中の `set_tax_rate()` / `set_relief()` からだけ変更する。`redistribute()` は在庫の範囲で物資を移す。表示が在庫や人物の仕事を直接書き換えない。

保存検証では経済日と時計、在庫の非負性、税率、忠誠・体力、仕事と人物の命令・作業位置、定員・枠の重複、日内労働が経過時間を超えていないこと、作物と資源残量、報告の月順を確認する。読み込みでデータの辞書をそのまま共有せず複製して保持する。

`World.is_time_stopped()` は手動停止または政治調整中にtrue。`begin_political_turn()` は冪等。`end_political_turn()` は未確定提案があれば拒否する。終了しても手動停止は変更しない。表示側はこの状態を変更命令で扱い、Spaceが政治調整を解除しないようにする。

読み込みは候補の世界で座標、ID、所有者、命令、経路、領土の地理的整合性を検証し、成功時だけコントローラが世界を置換して信号を付け替える。未確定の提案は無効な形でも有限な点列として保持する。保存は検証・一時ファイル書込・前回ファイル退避・置換の順。電源断耐性を保証するものではないが、最新データを読めなければ有効な前回バックアップを試す。

- `tests/world_smoke.gd`：状態・地理・交換・画面の接続を118項目で確認。
- `tests/world_save.gd`：保存・再開、破損拒否、バックアップ、世界の置換と再接続を44項目で確認。
- `tests/world_time.gd`：30倍時計、政治調整、命令の待機・再開、旧保存移行、日表示を24項目で確認。
- `tests/economy_smoke.gd`：生活・生産・現物税・保存と90日・360日シミュレーションを85項目で確認。
- `tests/economy_preview.gd`：経済画面の5枚の実描画。日次労働をまとめた検証用状態を使い、通常プレイに別の時計を追加しない。
- `tests/world_input.gd`：GodotのルートビューポートへGUI入力を注入して11項目を確認。論理座標を渡すため `push_input(event, true)` を使う。
- `tests/world_preview.gd`：実描画から7枚のPNGを保存。SubViewportのテクスチャも更新された後に取得する。
- `tests/smoke.gd`：変更しない旧版を46項目で確認。

テストはゲームバランスの証明ではない。写実的な地形・交通・経済の本格的モデル、長期の人物数、プレイヤーの理解しやすさは後続の観察と検証で扱う。

## 手動輸送と保存 version 4

`World.issue_transport(carrier, source, target, resource, amount)` と `resume_transport(carrier, returning)` が表示側からの入口。`transport.gd` の静的処理にWorldを渡し、参照循環を作らない。Worldのshipmentsに担当者IDをキーとしたsource/target/resource/amount/phaseを保持する。国庫は口座ID -1、個人は人物ID。自国住民のみが担当し、仕事の枠を解放する。

pickupは出発元から引いた予約、delivery/return/held/held_returnは積載済み荷物。同じamountを在庫と荷物に二重計上しない。予約時と引渡時に在庫を変更し、総量は国庫＋個人在庫＋予約・荷物で計算する。積載後は即時返金せず、返送先に到着して戻す。配送時に生産所得を増やさない。国庫からの食料配送は月報の配給量へ加える。

毎3ゲーム秒、人物移動後に受渡と追従経路を更新する。道路・海路はまだ扱わず既存の陸路探索を使う。届け先が到達不能になったら積載を保持して停止する。政治調整・手動停止では共通時計ごと停止する。

保存形式4はshipmentsを必須とし、担当者・量・口座・phase・仕事との競合・人物命令との一致を候補世界上で検証する。旧形式3は空の輸送状態で移行する。税と既存配給の抽象化は継続する。

`tests/transport_smoke.gd` は予約の競合、物資総量、橋、移動先追従、停止・返送・再開、保存の各段階、不正保存、UI接続を確認する。`tests/transport_preview.gd` は配送中・保持中・完了後の実描画を保存する。
